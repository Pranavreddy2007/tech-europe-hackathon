# GovMind API reference

Base URL (live): `https://driftypencil--govmind-web.modal.run` · locally: `http://localhost:8000`

All request and response bodies are JSON and are defined as Pydantic models (`backend/govmind/api.py`, `backend/govmind/schemas.py`), so FastAPI validates them and publishes an OpenAPI spec at **`/openapi.json`** (interactive docs at **`/docs`**).

## 1. Dashboard API

| Method | Path | Response | Description |
|---|---|---|---|
| `GET` | `/api/health` | `HealthResponse` | Treasury summary + active proposals (drives the DAO Health panel) |
| `GET` | `/api/members` | `list[GroupMemberOut]` | Members GovMind knows on Telegram/WhatsApp |
| `GET` | `/api/chain` | object | GovMind's own Endless account (address, EDS balance, explorer link) or `{"error": ...}` |
| `GET` | `/api/status` | object | Liveness: `{"name": "GovMind", "status": "ok", ...}` |
| `GET` | `/charts/{name}` | `image/png` | Charts generated by the agent (`chart_<ms>.png`) |
| `GET` | `/` | HTML | The dashboard (static Next.js export) |

## 2. Triggers

Triggers start an agent run and **return when the run finishes** (typically 13–40 s) with `{"trigger": "<name>", "response": "<agent's final answer>"}`. Runs are serialised: a second trigger waits for the current run. Every run streams its steps over Socket.IO (section 4).

| Method | Path | Body | What the agent does |
|---|---|---|---|
| `POST` | `/trigger/new-proposal` | `{"proposal_number": 49}` | Proposal intelligence: full briefing, posted to the DAO group |
| `POST` | `/trigger/submit-proposal` | none | **Demo:** a freshly funded attacker wallet submits proposal #N ("Emergency Liquidity Bridge", 70 EDS); GovMind analyses it and broadcasts a 🚨 GOVERNANCE ALERT if risky |
| `POST` | `/trigger/vote-check` | none | Vote mobilisation: finds non-voters, sends personal nudges, posts a summary |
| `POST` | `/trigger/treasury-check` | none | Treasury health check with chart and alerts |
| `POST` | `/trigger/attack-check` | none | Governance attack scan (all four patterns), alert with evidence |
| `POST` | `/trigger/ask` | `{"question": "...", "conversation_history": ["..."]?}` | Answers a question and posts it to the group |
| `POST` | `/trigger/create-proposal` | `{"title", "body", "proposer_address"?, "requested_amount"?, "voting_days"?}` | Creates a proposal (DB + on-chain record) and announces it |
| `POST` | `/trigger/cast-vote` | `{"proposal_number", "voter_address", "vote": "for\|against\|abstain", "voting_power"?}` | Casts a vote (DB + on-chain record) and confirms it |
| `POST` | `/trigger/whatsapp-demo` | `{"from": "447700900001", "name": "Alice Chen", "text": "..."}` | **Demo:** pushes a member message through the real inbound pipeline (tracking, history, agent run, reply) |
| `POST` | `/trigger/reset-demo` | none | Reloads the MetaDAO demo data and clears conversation state (Telegram subscribers are kept) |
| `POST` | `/trigger/simulate-members` | `{"whatsapp_ids": ["..."]?}` | Adds demo members |
| `POST` | `/trigger/track-member` | `{"whatsapp_id", "display_name"?}` | Tracks a member |
| `POST` | `/trigger/link-wallet` | `{"whatsapp_id", "wallet_address"}` | Links a member to an Endless wallet |

Example:

```bash
curl -X POST https://driftypencil--govmind-web.modal.run/trigger/new-proposal \
  -H 'Content-Type: application/json' -d '{"proposal_number": 49}'
```

Member ids are WhatsApp numbers (digits only) or `tg:<chat id>` for Telegram. The field is named `whatsapp_id` for historical reasons.

## 3. Webhooks

### Telegram: `POST /webhook/telegram`

- Registered automatically on startup via `setWebhook` (when `TELEGRAM_BOT_TOKEN` and `PUBLIC_BASE_URL` are set), with `allowed_updates = ["message", "my_chat_member"]`.
- **Authentication:** requests must carry `X-Telegram-Bot-Api-Secret-Token` matching the configured (or derived) secret; anything else gets `401`.
- Body: a Telegram [`Update`](https://core.telegram.org/bots/api#update), parsed into Pydantic models (`govmind/telegram/models.py`). Handled asynchronously; the endpoint returns immediately.
- Behaviour:
  - **Private chat:** `/start` subscribes the member to alerts and shows the command keyboard. Any other text is answered privately.
  - **Group chat:** the bot learns the group (on `my_chat_member` or the first message), tracks senders, new members and mentions, auto-links wallet addresses, and answers questions **in the group**.

### WhatsApp: `GET /webhook/whatsapp`, `POST /webhook/whatsapp`

- `GET` is Meta's verification handshake: returns `hub.challenge` when `hub.mode=subscribe` and `hub.verify_token` matches `WHATSAPP_VERIFY_TOKEN`, otherwise `403`.
- `POST` receives message events. **Authentication:** `X-Hub-Signature-256` is checked as HMAC-SHA256 of the raw body with `WHATSAPP_APP_SECRET` (`401` on mismatch). The body is parsed into `WebhookPayload` (`govmind/whatsapp/models.py`); unknown payloads are ignored with `{"status": "ignored"}`.
- Handles text, interactive list/button replies (the "menu" command list), and duplicate deliveries (deduplicated by message id).

## 4. Socket.IO events

Connect with any Socket.IO v4 client to the base URL (same origin as the dashboard). Server → client events:

| Event | Payload | Dashboard effect |
|---|---|---|
| `agent:start` | `{trigger, timestamp}` | New run; graph resets |
| `agent:tool-start` | `{tool, input, timestamp}` | Node lights up, edge animates |
| `agent:tool-result` | `{tool, result, timestamp}` (truncated to about 2 KB) | Node marked visited |
| `agent:complete` | `{response, steps: [{tool, description}], timestamp}` | Run COMPLETE, response panel |
| `agent:error` | `{error, timestamp}` | Run ERROR |
| `whatsapp:message-received` | `{type: "dm"\|"group", text, senderUid, senderName, platform, timestamp}` | Incoming message in the Live Feed (`platform` is `Telegram`, `Telegram group` or `WhatsApp`) |
| `whatsapp:message-sent` | `{type, text, recipientUid, imageUrl, recipientCount, platform, timestamp}` | Outgoing message (with chart image) in the Live Feed |

Event names keep a `whatsapp:` prefix for compatibility; they cover every channel.

## 5. Agent tools (24)

Each tool's parameters are a Pydantic model (`backend/govmind/agent/tools.py`); this reference is generated from those models. Arguments are validated before the tool runs, and unknown arguments are rejected. Every tool returns a typed Pydantic result (`schemas.py`) serialised to JSON, or `{"error": "..."}`.

### Governance

#### `get_active_proposals`

Returns all governance proposals with status "active", including vote tallies and participation rates. Use this to see what proposals need attention.

_No parameters._

#### `get_proposal_detail`

Returns the full text, metadata, and vote breakdown for a specific proposal. Use this when you need to summarise or analyse a specific proposal.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `proposal_number` | integer | yes | The proposal number (e.g., 48) |

#### `get_voting_status`

Returns who has voted and who has NOT voted on a given proposal, plus time remaining and participation rate. Use this for vote mobilisation.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `proposal_number` | integer | yes | The proposal number (e.g., 48) |

#### `get_member_vote_history`

Returns a specific member's past voting record and patterns. Use this to personalise nudge messages based on how they voted on similar proposals.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `address` | string | yes | The wallet address |

#### `create_proposal`

Creates a new governance proposal in the DAO. Records it in the database and on Endless Chain for immutable proof. Returns the new proposal number.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `title` | string | yes | Title of the proposal |
| `body` | string | yes | Full text/description of the proposal |
| `proposer_address` | string | yes | Wallet address of the proposer |
| `requested_amount` | number | yes | Amount of EDS requested (0 if no funding needed) |
| `recipient_address` | string \| null | no | Wallet address to receive funds if proposal passes (defaults to proposer) |
| `voting_days` | number \| null | no | Number of days the vote stays open (default: 5) |

#### `cast_vote`

Casts a vote on an active proposal. Records the vote in the database and on Endless Chain. Each address can only vote once per proposal.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `proposal_number` | integer | yes | The proposal number to vote on |
| `voter_address` | string | yes | Wallet address of the voter |
| `vote` | `for` \| `against` \| `abstain` | yes | The vote choice |
| `voting_power` | number \| null | no | Voting power (token balance). Default: 1 |

#### `get_group_members`

Returns every DAO member who has messaged GovMind on WhatsApp (and so receives DAO broadcasts). Includes their WhatsApp ID, message count, and last active time. Use this to identify who to nudge.

_No parameters._

#### `get_non_voters`

Returns all members who have NOT voted on a specific proposal. Cross-references registered DAO members and members reachable on WhatsApp. Returns their WhatsApp IDs for sending nudge messages.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `proposal_number` | integer | yes | The proposal number (e.g., 48) |

### Wallets & Endless Chain

#### `link_wallet`

Links a WhatsApp user to an Endless Chain wallet address. Use this when a user shares their wallet address (Base58 format like "4T1Jmi...K2qf" or hex "0x..."). This enables on-chain operations for that user — checking their EDS balance, sending them EDS, etc.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `whatsapp_id` | string | yes | The WhatsApp ID (phone number, digits only) to link |
| `wallet_address` | string | yes | The Endless Chain wallet address (Base58 like 4T1Jmi...K2qf, or 0x hex) |

#### `get_wallet_for_user`

Looks up the linked Endless Chain wallet address for a WhatsApp user. Returns the wallet address if one has been linked, or null if the user hasn't shared their wallet yet.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `whatsapp_id` | string | yes | The WhatsApp ID (phone number, digits only) to look up |

#### `get_onchain_balance`

Reads the real EDS (Endless) token balance for any wallet address on Endless Chain. Use this to verify actual on-chain balances in real-time, cross-reference treasury holdings, or check a member's funds.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `address` | string | yes | The wallet address |

#### `transfer_eds`

Initiates an actual EDS token transfer on Endless Chain. Use this for treasury disbursements, grant payments, or any authorized on-chain transfer. Returns the transaction hash and explorer URL.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `recipient_address` | string | yes | The recipient wallet address (Base58 or 0x hex) |
| `amount_eds` | number | yes | Amount of EDS tokens to transfer |
| `reason` | string | yes | The reason for this transfer (e.g., "Grant payment for Proposal #48") |

#### `record_action_onchain`

Records an agent action as an immutable on-chain audit trail entry on Endless Chain. Creates a verifiable transaction that proves this action happened. Use after important governance decisions.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `action_type` | string | yes | Type of action to record (e.g., "proposal_summary", "attack_alert", "treasury_disbursement") |
| `summary` | string | yes | Brief summary of what was decided or detected (hashed and stored on-chain) |

### Treasury

#### `get_treasury_summary`

Returns current treasury balances, allocation breakdown, monthly burn rate, runway in months, and concentration risk assessment.

_No parameters._

#### `get_treasury_transactions`

Returns recent treasury transactions. Can filter by direction (inflow/outflow), category, and time period.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `direction` | `inflow` \| `outflow` \| null | no | Filter by transaction direction |
| `category` | string \| null | no | Filter by category (e.g., contributor_payment, grant, swap, revenue) |
| `days_back` | integer \| null | no | Number of days to look back (default: 30) |
| `limit` | integer \| null | no | Max number of transactions to return (default: 20) |

### Security

#### `get_token_transfers`

Returns recent governance token ($GOV) transfer activity. Use this for attack detection — look for coordinated accumulation, new wallets, same-source funding.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `hours_back` | integer \| null | no | Number of hours to look back (default: 48) |

#### `get_wallet_profile`

Returns information about a wallet address including age, transfer history, token balance, and whether it belongs to a known DAO member. Use for proposer risk assessment and attack investigation.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `address` | string | yes | The wallet address |

### Messaging (Telegram / WhatsApp)

#### `send_group_message`

Posts a message to the DAO group chat on Telegram (and to members subscribed on Telegram/WhatsApp). When you were messaged from the group, this answers in that group. Use this to post summaries, alerts, answers, and reminders everyone should see.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `text` | string | yes | The message text to broadcast to DAO members |
| `image_url` | string \| null | no | Optional chart_url from generate_chart to attach as an image |

#### `send_direct_message`

Sends a private WhatsApp message to one DAO member. Use this to reply to the member you are talking to, and for personalised vote nudges (pass their whatsapp_id).

| Parameter | Type | Required | Description |
|---|---|---|---|
| `whatsapp_id` | string \| null | no | Member ID of the recipient: a WhatsApp number (digits only) or a Telegram id like tg:123. Omit to reply to the member who sent the current message. |
| `text` | string | yes | The message text to send |
| `image_url` | string \| null | no | Optional chart_url from generate_chart to attach |

### Utility

#### `query_data`

Execute a read-only SQL query against the DAO database for ad-hoc data questions. Only SELECT queries are allowed. Tables: proposals, votes, members, group_members, treasury_transactions, treasury_balances, token_transfers, knowledge, agent_actions_log, nudge_tracking.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `sql` | string | yes | The SQL SELECT query to execute |

#### `generate_chart`

Generates a chart image (PNG) from provided data. Returns a chart_url. Pass it as image_url to send_group_message or send_direct_message so members see the chart inline in WhatsApp.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `chart_type` | `bar` \| `line` \| `pie` \| `doughnut` | yes | Type of chart to generate |
| `title` | string | yes | Chart title |
| `labels` | array of string | yes | Labels for the data points |
| `datasets` | array of object | yes | Datasets to chart |

#### `get_knowledge`

Retrieves team corrections and definitions from the knowledge base. Always check this before answering questions to ensure you use team-specific definitions.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `term` | string | yes | The term or topic to look up (e.g., "runway", "core contributor") |

#### `store_knowledge`

Stores a new team correction or definition. Use when a team member provides a correction (e.g., "runway should exclude locked staking").

| Parameter | Type | Required | Description |
|---|---|---|---|
| `term` | string | yes | The term being defined or corrected |
| `definition` | string | yes | The definition or correction |
| `source_user` | string | yes | Who provided this correction |

#### `log_action`

Records what the agent did and why. Call this as the LAST step of every action for the audit trail.

| Parameter | Type | Required | Description |
|---|---|---|---|
| `action_type` | `proposal_summary` \| `vote_nudge` \| `treasury_alert` \| `attack_alert` \| `query_answer` \| `knowledge_update` | yes | Type of action taken |
| `trigger` | `scheduled` \| `new_proposal` \| `user_question` \| `anomaly_detected` \| `manual_trigger` | yes | What triggered this action |
| `reasoning` | string | yes | Brief explanation of why you took this action and what you found |
| `message_sent` | string \| null | no | The message you sent on WhatsApp (if any) |


## 6. External APIs GovMind calls

| API | Used for | Where |
|---|---|---|
| **Google Gemini** (via Pydantic AI `GoogleModel`) | The agent's reasoning and function calling | `agent/runner.py` |
| **Telegram Bot API**: `sendMessage`, `sendPhoto`, `sendChatAction`, `getChatMember`, `getMe`, `setWebhook`, `setChatMenuButton` | Replies, group posts, alerts, charts, typing indicator, duplicate-alert check, webhook setup | `telegram/client.py` |
| **WhatsApp Cloud API** (Graph API `/{phone_number_id}/messages`) | Text, image and interactive list messages, read receipts | `whatsapp/client.py` |
| **Endless Chain** (TypeScript SDK → Endless REST RPC) | EDS balances, EDS transfers, on-chain audit records, testnet faucet | `chain/endless.mjs`, `services/blockchain.py` |
